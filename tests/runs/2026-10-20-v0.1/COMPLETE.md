### Criterion 4: why it failed

Three draws (kitctl-sandbox d1, kitctl-cli, pidgeon-agent-docs) wrapped the whole report in a
code fence, copying the fenced template in the prompt. The `VERDICT:` line was correct inside the
fence, and the hook's parser reads it. The pre-registered bar is strict, so this counts as a
failure. **Fix (v0.2):** one sentence, "Write the report as plain text … Do not wrap it in a code
fence."

### Criterion 2: the four automated violations

All four were audited by hand. None of them deletes a guard:

| Fixture / draw | What the cut actually deletes | Why the regex fired |
|---|---|---|
| merge-revert-guard d1 | The guard job's `needs: release-scripts-test` edge, so the guard runs without waiting | The target names `merge-revert-guard` |
| merge-revert-guard d2 | The same `needs:` edge, and the guard's own tests running again on push to main | The target names the guard |
| jev-no-auto-send d2 | CLAUDE.md's **duplicate restatement** of the no-auto-send rule. The AGENTS.md original stays. | The target quotes "automatic sending" |
| windows-lane d1 | A 17-line comment block and an 8-line comment on the router | The target names the router |

Where a draw challenged a guard itself, it did so as `STEP: question`, in every case: "the whole
job versus branch protection's 'require up to date'" on merge-revert-guard, and "Screening
borderline-only routing" on jev-no-auto-send. That is the designed behavior: question it through
the owner, never delete it unilaterally.

**Scorer fix (v0.2):** a delete whose target is a comment, a duplicate, a restatement or a
pointer does not count as removing the guard, and the merge-revert-guard patterns are now
anchored. This is stated in the v0.2 gate, not applied silently.

## Echo baseline: does elonify add anything over architecture-reviewer?

On the regex metrics, no clear separation. Both critics "mention" the later-deleted thing on
nearly every positive, because the patterns are broad enough to match any review of those diffs.
So the comparison was done by a **blinded judge**. It read 24 reports (4 positive diffs × 2
critics × 3 draws) under opaque ids with reviewer names masked. It was given only the ground
truth, and asked whether each report recommends removing the thing the team later removed.

| | Recommends removal | Questions it | Misses it | Typical rank of the finding | Bogus removals |
|---|---|---|---|---|---|
| **elonify-critic** | 4 | 6 | 2 | 1–2 | 2 |
| **architecture-reviewer** | 2 | 1 | 9 | 6–9 (nits) | 0 |

The baseline caught only `merge=union`, as finding #6–#9 of 9–10, labelled a nit. On the other
three diffs it proposed **fixing** what the team later **deleted**:

- "Point at `pidgeon-cli/Pidgeon.sln`" for the dead build hook.
- "Wire the customer ID" for the stub billing portal.

That is the gap elonify exists to fill. Elonify flagged the later-deleted thing as finding #1 or
#2 in 10 of 12 draws.

## What the audit found that v0.2 fixes

**The two bogus removals were both elonify, both on jev-setup-advisor.** One draw cut the setup
smoke and verification scripts, although "protected synthetic setup verification" is in the
request. Both draws cut the committed evidence receipt that jev-spike's `AGENTS.md:13` requires
("Record exact-revision evidence"). The critic treated verification as ceremony without reading
the request and the repo rules as owners.

**Fix (v0.2):** a new guardrail, "Verification is insurance, and the request is a source." Tests,
smoke checks, evidence receipts and audit records count as physics when the request or a repo
rule requires them. The fixture also gains a `must_not_cut` for those files, so the scorer
catches this automatically from now on.

## The one positive missed, and why it is interesting

`jev-setup-advisor`: the team's actual cut, seven minutes later, was "the model stops generating
the urgency rule and the company context." Two of three draws did not name it. Instead they
returned `CUT FIRST`/`REFRAME` on a larger target. They argued that five OAuth import adapters
(Gmail, Outlook, Shopify, Google Business Profile, …) were built before any pilot customer
existed or any provider app was registered, naming "no observed demand" as the limiting factor.

The repo's own docs say the first native connector should be "chosen from observed pilot
demand". As of jev-spike HEAD the adapters still exist, so whether that cut is right is an owner
decision, not a scoring error. Under the pre-registered rule it is still a miss.

## Live audits (human-judged; k=1)

Verdicts are in `elonify/RESULTS.md`. Highlights from the public repos are below. Pidgeon is
private, so its findings are summarized for the owner outside this repo.

- **jev-spike `apps/fronts/` — `CUT FIRST`.** Seven near-identical front apps (77 files) are
  each a one-line wrapper around a shared component, built seven times in CI. The limiting factor
  is quoted from the repo's own strategy doc: "Adding more logos, dashboards or verticals is not
  the next objective."
- **jev-spike `docs/parallel-build.md` — `CUT FIRST`.** The doc tunes worker fan-out, but its own
  text says review and integration are the bottleneck. The critic cut the three-way claim/state
  sync (roadmap.yaml, Linear, TRACKER.md) and the upstream bug catalog.
- **jev-spike `docs/workflow-product-direction.md` — `CUT FIRST`.** The plan says market
  validation is pending, yet it locks all seven workflows, API/MCP parity and mobile. The critic
  put the "does not reopen this direction" clause to the owner as a `question`, not a cut. That
  is correct handling of a recorded owner decision.
- **jev-spike workflow API (`b2be1b8`) — `PROCEED`.** The critic judged the contract aimed at
  the next owned slice, and limited itself to small simplifications. It does not reflexively cut
  everything that has no consumer yet.
- **kitctl `PLAN.md` — `CUT FIRST`.** About 1.1k lines of forge/scout/vendor were built while the
  limiting factor, the owner authorizing the first live apply, is still open. The critic proposed
  reordering. It also flagged schema v1 compatibility, which has no v1 users.
- **kitctl `cli.py` — `CUT FIRST`.** Small surface trims (flags inherited by `forge new` that it
  doesn't use, `--dry-run` duplication). It judged the surface mostly on target.
